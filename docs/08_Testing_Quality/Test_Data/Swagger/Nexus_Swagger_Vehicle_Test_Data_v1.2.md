## 1. Purpose

This document provides Swagger-ready test payloads for the **Vehicle** API using the current locked `vehicles` database columns supplied for ONE Classics Nexus.

The key correction in this version is:

> Vehicle payloads use `vehicleTypeId` mapped from database column `vehicle_type_id`.  
> Vehicle payloads do **not** use a free-text `vehicleType` field.

---

## 2. Source Vehicle Columns

The following database columns define the current `vehicles` table surface area:

| Database Column | API JSON Field | Request Usage | Response Usage | Notes |
|---|---|---:|---:|---|
| `vehicle_id` | `vehicleId` | No | Yes | Generated by API/database; passed in route for GET/PUT. |
| `vehicle_type_id` | `vehicleTypeId` | Yes | Yes | Foreign key/reference to `vehicle_types`. Not `vehicleType`. |
| `vin` | `vin` | Yes | Yes | Classic vehicles may use shorter pre-1981 VINs. |
| `year` | `year` | Yes | Yes | Integer model year. |
| `make` | `make` | Yes | Yes | Vehicle manufacturer. |
| `model` | `model` | Yes | Yes | Vehicle model. |
| `trim` | `trim` | Yes | Yes | Nullable/optional. |
| `series_name` | `seriesName` | Yes | Yes | Example: `K10`, `C10`, `Model A`. |
| `body_style` | `bodyStyle` | Yes | Yes | Example: `Short Bed Pickup`. |
| `drivetrain` | `drivetrain` | Yes | Yes | Example: `4x4`, `RWD`. |
| `engine` | `engine` | Yes | Yes | Engine description. |
| `transmission` | `transmission` | Yes | Yes | Transmission description. |
| `mileage` | `mileage` | Yes | Yes | Integer odometer value. |
| `odometer_unit` | `odometerUnit` | Yes | Yes | Example: `miles`. |
| `exterior_color` | `exteriorColor` | Yes | Yes | Exterior color. |
| `interior_color` | `interiorColor` | Yes | Yes | Interior color. |
| `title_status` | `titleStatus` | Yes | Yes | Example: `Clean`. |
| `authenticity_profile` | `authenticityProfile` | Yes | Yes | Example: `Restomod`, `Mostly Original`. |
| `restoration_level` | `restorationLevel` | Yes | Yes | Example: `Frame-Off Restored`. |
| `documentation_level` | `documentationLevel` | Yes | Yes | Example: `Strong`. |
| `overall_condition_score` | `overallConditionScore` | Yes | Yes | Decimal 0.00–5.00 unless API validation says otherwise. |
| `has_red_flags` | `hasRedFlags` | Yes | Yes | Boolean. |
| `notes` | `notes` | Yes | Yes | General vehicle notes. |
| `ownership_notes` | `ownershipNotes` | Yes | Yes | Ownership/provenance notes. |
| `created_at_utc` | `createdAtUtc` | No | Yes | System-managed timestamp. |
| `updated_at_utc` | `updatedAtUtc` | No | Yes | System-managed timestamp. |

## 10. Swagger Execution Order

Run the vehicle tests in this order:

1. Confirm `vehicle_types` seed/reference data exists.
2. POST 1970 Chevrolet K10.
3. Capture returned `vehicleId`.
4. GET `/api/vehicles/{vehicleId}`.
5. PUT `/api/vehicles/{vehicleId}` with updated mileage/notes.
6. GET `/api/vehicles/{vehicleId}` again and verify changes persisted.
7. POST 1929 Ford Model A.
8. Execute negative validation tests.
9. Execute duplicate VIN test.
10. Execute unknown ID GET/PUT tests.

## 11. Repository/API Validation Checklist

| Check | Expected Result |
|---|---|
| `vehicle_type_id` maps to `vehicleTypeId` | Yes |
| `series_name` maps to `seriesName` | Yes |
| `odometer_unit` maps to `odometerUnit` | Yes |
| `ownership_notes` maps to `ownershipNotes` | Yes |
| `created_at_utc` is not accepted in POST/PUT body | Yes |
| `updated_at_utc` is not accepted in POST/PUT body | Yes |
| `vehicle_id` is generated or route-bound, not body-bound | Yes |
| POST does not use `vehicleType` | Yes |
| PUT does not use `vehicleType` | Yes |
| API returns ProblemDetails for validation failures | Yes |

---

## 12. Notes for Current Nexus Implementation

- Use camelCase JSON names in Swagger request/response bodies.
- Use snake_case only in SQL and repository mappings.
- `vehicleTypeId` should be treated as a foreign-key/reference value.
- `createdAtUtc` and `updatedAtUtc` are system-managed response fields.
- `vehicleId` is expected in responses and route parameters, not POST/PUT request bodies.
- `vin` uniqueness should be enforced at the database and application/API level.
